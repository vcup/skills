# Ensemble 三路径隔离：最小设计比较

> **历史审阅与设计比较。** 文档闭合相关发现已通过[文档补齐与审阅处分](<DOC-CLOSURE-RESULT.md>)处理；本文的路径隔离建议及后续纠正最终以[三路径分发约定](<../DISTRIBUTION.md>)为准，不代表当前待办。行号及“当前”等措辞均为当时定位；本次迁存未重新安装或运行验收。纯 skill 已决定保留原 Git 安装源 `vcup/skills`，不是待选发行地址。

**最终约定与本稿的关系：** 三种方案的比较及反例继续保留；最终设计采用共用方法源与三个静态分发物，纯 skill 不另建发行仓，继续使用 `vcup/skills`。OMP 可保留 `@vcup/skills` 包身份及其它既有技能；母仓库可以共同维护并介绍三条路径，但其多路径说明不得进入安装后的技能目录或插件包。下文“根说明只保留纯 skill”等是当时建议，不能替代[最终分发约定](<../DISTRIBUTION.md>)对源码仓和安装阅读闭包的区分。

原审阅依据仅限[根说明](<../../../README.md>)、[包元数据](<../../../package.json>)、[当时技能入口](<../../../skills/ensemble/SKILL.md>)、[DSH 实施草案前 75 行](<../IMPLEMENTATION.md>)。未读取安装器源码、参考正文或角色正文；发现优先级和安装语法尚未验证。
当前入口第 15 行已混入 OMP 状态工具和 managed 分支，第 51 行混入插件/手写记录分支；DSH 草案第 7、69 行承诺同包分发并保留 OMP 消费路径。这些不是换三个入口标题就能隔离的。

推荐：共用无平台方法源，固定装配成三个独立、闭合的静态分发物；隔离单位是完整安装与阅读闭包，不只是入口正文。
实现上限是一个固定拼接脚本与三份显式资源清单；不建条件模板 DSL、运行时探测或通用发布框架。

| 方案 | 最小成本与风险 | 判断 |
| --- | --- | --- |
| 三份手写 | 初始工具最少；但方法、按需参考、角色片段和链接都需分别维护，修正容易只到一条路径 | 可作短期过渡；若坚持采用，必须接受三份方法副本的维护成本 |
| 共用方法＋三入口静态产出 | 多一个固定装配步骤；方法改一次，各路径资源独立落盘并可完整检查 | 推荐；共享源只服务构建，不成为安装后的跨包依赖 |
| 运行时条件过滤 | 入口看似一份，却要识别环境、处理未知环境并约束所有后续加载；发现冲突发生在过滤前 | 不采用，无法提供结构性的隔离保证 |

三条分发边界：

- 纯 skill：保留 `npx skills add vcup/skills --skill ensemble -a <agent>`；Git 可发现树中只提交这一份可安装的同名入口，生成正文及其全部引用一并提交，不依赖 npm 发布钩子或安装时构建。
- OMP：从独立发布包根安装；根 `skills/` 中只有 OMP 版 ensemble，并配套本路径 roles、工具和说明。不得同时在旧仓库根保留纯入口自动发现、又额外注册一个 OMP 同名入口；确切发现行为需原生安装验收。
- DSH：独立插件包提供 Host/root、client、skill provider 和固定枚举 reference；其静态正文、资源和包首页只讲 DSH，managed 操作不带纯 skill 手写模板或 OMP 备用路径。
- 共用源不使用可被发现为技能的入口格式；OMP/DSH 的同名安装入口只进入各自发布物，不作为额外可发现入口提交到纯 skill 的 Git 树。包的 `files`/`exports` 不能被当作 Git 技能发现隔离器。
- 每条清单覆盖入口、按需参考、模板、术语/模式、自动加载角色、包首页与全部相对链接；生成后引用只能落在本分发物内。不得由 DSH reference 直接读取含平台分支的公共原稿。

根兼容承诺需要显式调整：

- [DSH 草案第 7 行](<../IMPLEMENTATION.md>)改为独立 DSH 包；[第 69 行](<../IMPLEMENTATION.md>)不再要求 DSH tarball 带原 OMP 入口或保持其消费路径。根包不再承担 ensemble 一包多平台安装合同。
- 旧 `omp install github:vcup/skills` 不再作为 ensemble 当前受支持入口；迁移通知只指向新 OMP 目标。若已有发布版本，可冻结为历史兼容线；不能增加隐式转发、同名回退来伪称完全兼容。
- [根说明](<../../../README.md>)作为纯 skill Git 入口只保留该路径的 ensemble 安装/使用说明；OMP、DSH 各自发布根有自己的首页，不能复制混合首页或链接回混合指南。维护者设计资料不进入安装阅读闭包。
- 只调整 ensemble 的分发和相关根合同；其它技能正文与目录不改版，但旧根 OMP 安装原先连带提供多个技能的兼容变化必须明示，不能声称对整个旧安装包毫无影响。

验收设计：分别用实际 Git 来源发现、OMP 独立包根自动发现、DSH 打包安装检查唯一 ensemble；穷举加载参考和自动角色，验证每个相对链接及包首页仍在本路径闭包内；检查产物与源一致。这些是待做检查，本轮未执行。

三个最容易漏的反例：

1. npm 包验证成功，纯 skill 的 Git 安装却找不到未提交的生成入口，或扫到两个同名入口；发布清单和 exports 都没有解决 Git 树发现问题。
2. 新 OMP 入口写得正确，但旧根 `skills/ensemble` 仍被自动发现，导致同名覆盖或重复；修改导出路径、声称“优先加载 OMP”不等于消除冲突。
3. DSH 首次加载无其它平台字样，随后 reference 返回公共原稿第 15 行的 OMP 指令，或参考/自动角色/包首页通过相对链接回到混合说明；只检查入口会漏掉整个后续阅读链。
